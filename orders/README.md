# Конструктор наказів для школи — MVP 1.4

## Як запустити

1. Розпакуйте архів.
2. Відкрийте `index.html` у Chrome, Edge або Brave.
3. У розділі **Мій заклад** внесіть реквізити, фірмовий бланк і довідник працівників.
4. У **Наказах** оберіть місяць і тему. Стандартні формулювання вже підготовлені — вводяться переважно лише змінні дані.
5. За потреби натисніть **Зберегти наказ**, щоб повернутися до нього пізніше.
6. Перед друком відкрийте **Попередній перегляд**, перевірте документ і сформуйте DOCX або PDF через системний друк.

Сервер для звичайного використання не потрібний. `index.html` підключає classic bundle і працює через `file://`.

## Що змінилося у 1.4

- компактніший офіційний інтерфейс з вищим контрастом;
- місяці та категорія розміщені в одному рядку на широких екранах;
- картки наказів починаються вище, без великих декоративних блоків;
- універсальні шаблони винесені в окремий розділ унизу каталогу;
- додано розділ **Збережені**;
- наказ можна зберегти локально, відредагувати, створити копію або видалити;
- копія автоматично отримує поточну дату і порожній номер, щоб не дублювати номер старого наказу;
- збережені записи мають статус **Готовий** або **Чернетка**;
- налаштування закладу можна експортувати та імпортувати через JSON;
- JSON налаштувань може містити також збережений графічний бланк;
- збережені накази мають окремий JSON-експорт/імпорт із чітким попередженням про можливі персональні дані.
- фінальний експорт проходить через попередній перегляд і блокується без номера наказу;
- DOCX використовує штатну нумерацію Word, нумерацію сторінок із другої сторінки та формує заявлені додатки;
- нормативно чутливі шаблони вимагають зафіксувати перевірену чинну підставу;
- для наказів розрізняються реєстраційні серії: основна діяльність, кадрові питання, рух здобувачів освіти та адміністративно-господарські питання.

## Приватність

- мережеві запити заблоковані CSP (`connect-src 'none'`);
- накази не зберігаються автоматично — лише після явного натискання **Зберегти наказ**;
- профіль закладу і довідник працівників зберігаються локально;
- збережені накази зберігаються у IndexedDB; якщо браузер її блокує, застосунок має локальний fallback через `localStorage`;
- локальне сховище браузера **не є зашифрованим архівом**: на спільному комп'ютері не варто зберігати накази з чутливими персональними даними;
- DOCX формується у браузері, без передачі змісту на сервер;
- зовнішніх API, CDN, аналітики, Firebase Auth або Firestore немає.
- для роботи з персональними даними розміщуйте застосунок на окремому домені/субдомені: `localStorage` та IndexedDB спільні для всіх шляхів одного походження, а GitHub Pages не застосовує файл `_headers`.

## Нормативна відповідність

Детальна прив’язка правил експорту до офіційних актів і межі автоматичної перевірки наведені у [NORMATIVE.md](NORMATIVE.md).

## Перспективний план

Заплановану модель персонального кабінету з Firebase Authentication, Cloud Firestore, міграцією локальних даних і вимогами до безпеки описано у [ROADMAP.md](ROADMAP.md). Спільні кабінети закладу та ролі користувачів до першого етапу не входять.

## Розробка

Вихідний код залишається модульним у `js/*.js`. Після змін виконайте:

```bash
npm test
```

Команда перебудовує browser bundles і запускає Node-тести.
