# Конструктор наказів для школи — MVP 1.6

## Як запустити

1. Розпакуйте архів.
2. Відкрийте `index.html` у Chrome, Edge або Brave.
3. У розділі **Мій заклад** внесіть реквізити, фірмовий бланк і довідник працівників.
4. У **Наказах** скористайтеся одним із двох шляхів: знайдіть готовий наказ за назвою або темою чи відкрийте вільний наказ. Стандартні формулювання вже підготовлені — вводяться переважно лише змінні дані.
5. За потреби натисніть **Зберегти наказ**, щоб повернутися до нього пізніше.
6. Перед друком відкрийте **Попередній перегляд**, перевірте документ і сформуйте DOCX або PDF через системний друк.

Сервер для звичайного використання не потрібний. `index.html` підключає classic bundle і працює через `file://`.

## Що змінилося у 1.6

- бібліотека зросла до 54 шаблонів: атомізовано всі 32 реальні серпневі накази у п’яти тематичних етапах;
- додано режим роботи, освітню програму й навчальні плани, підготовку закладу, мережу класів та введення в дію рішень педагогічної ради;
- додано підготовку спортивних споруд, відповідального за електрогосподарство, завідувачів кабінетів, результати готовності закладу та відповідального за укриття; перероблено шаблони класних керівників і педагогічного навантаження;
- додано інклюзивне навчання, медичне обслуговування учнів, медичні огляди працівників і розподіл першокласників; наказ про харчування перероблено з графіком, бракеражною комісією та документацією;
- додано готовність до осінньо-зимового періоду, постійно діючу технічну комісію, профілактику шкідливих звичок, Клас безпеки, безпечне і здорове освітнє середовище, Перший урок, «Учителя року» та систему оцінювання;
- нові сценарії мають типові нормативні підстави з довідника; формальний аудит 12.08.2026 підтвердив чинність 40 із 51 акта, а для 11 неоднозначних записів конструктор показує попередження;
- додано багаторівневі пункти з виконавцем за посадою та окремим строком виконання;
- вільний наказ підтримує багатоабзацну преамбулу й таблиці безпосередньо в розпорядчій частині;
- нормативні підстави можна вибирати з версійованого довідника з офіційними URL і датою фіксації реквізитів;
- лінтер виявляє пошкоджені дати й навчальні роки, розбіжність року між заголовком і текстом, минулі строки та незаповнені реквізити;
- у розділі **Збережені** можна сформувати 32 чернетки серпневого пакета й перевірити накази між собою; усі 32 чернетки відкриваються у відповідних тематичних шаблонах;
- корпус `samples/` виключено з Git і Firebase Hosting, а DOCX не записує назву закладу в поле автора;
- заголовок наказу вирівняно від лівого поля;
- інтерфейс зведено до двох зрозумілих шляхів: готовий або вільний наказ; у великих формах типові значення згорнуті, а в пункті вільного наказу одразу показано лише виконавця, текст і строк;

## Що було додано у 1.5

- компактніший офіційний інтерфейс з вищим контрастом;
- місяці та категорія розміщені в одному рядку на широких екранах;
- картки наказів починаються вище, без великих декоративних блоків;
- універсальні шаблони винесені в окремий розділ унизу каталогу;
- додано розділ **Збережені**;
- наказ можна зберегти локально, відредагувати, створити копію або видалити;
- копія автоматично отримує поточну дату і порожній номер, щоб не дублювати номер старого наказу;
- збережені записи мають статус **Готовий** або **Чернетка**;
- налаштування закладу можна експортувати та імпортувати через JSON;
- JSON налаштувань може містити також збережений графічний бланк;
- збережені накази мають окремий JSON-експорт/імпорт із чітким попередженням про можливі персональні дані.
- фінальний експорт проходить через попередній перегляд і блокується без номера наказу;
- DOCX використовує штатну нумерацію Word, нумерацію сторінок із другої сторінки та формує заявлені додатки;
- нормативно чутливі шаблони вимагають зафіксувати перевірену чинну підставу;
- для наказів розрізняються реєстраційні серії: основна діяльність, кадрові питання, рух здобувачів освіти та адміністративно-господарські питання.
- серію можна скоригувати відповідно до локальної інструкції та номенклатури справ;
- застосунок попереджає про локальний дублікат номера і пропонує наступний номер у межах року та серії;
- затверджені документи отримують гриф «ЗАТВЕРДЖЕНО», а звичайні додатки — повну відмітку з назвою закладу;
- доступні опційні реквізити «Підстава:» і «З наказом ознайомлені»;
- багатосторінковий друк використовує окремий контейнер і поля A4 на кожній сторінці;
- помилки показуються біля полів, а мобільний перегляд A4 масштабується за шириною;
- незавершена робоча форма тимчасово автозберігається у `sessionStorage` і може бути відновлена після перезавантаження вкладки.

## Приватність

- мережеві запити заблоковані CSP (`connect-src 'none'`);
- робоча форма тимчасово автозберігається лише в межах поточної браузерної сесії; до бібліотеки наказ потрапляє тільки після явного натискання **Зберегти наказ**;
- профіль закладу і довідник працівників зберігаються локально;
- збережені накази зберігаються у IndexedDB; якщо браузер її блокує, застосунок має локальний fallback через `localStorage`;
- локальне сховище браузера **не є зашифрованим архівом**: на спільному комп'ютері не варто зберігати накази з чутливими персональними даними;
- DOCX формується у браузері, без передачі змісту на сервер;
- зовнішніх API, CDN, аналітики, Firebase Auth або Firestore немає.
- локальний корпус реальних документів `samples/` не входить до Git і не публікується Firebase Hosting; не прибирайте ці правила ігнорування перед деплоєм.
- для роботи з персональними даними розміщуйте застосунок на окремому домені/субдомені: `localStorage` та IndexedDB спільні для всіх шляхів одного походження, а GitHub Pages не застосовує файл `_headers`.

## Перспективний план

План перетворення реальних зразків на бібліотеку із сотень зручних сценаріїв описано у [TEMPLATE_LIBRARY.md](TEMPLATE_LIBRARY.md). Документ містить просте пояснення для завуча, правила для ШІ-агента, вимоги до приватності й критерії готовності шаблону.

Заплановану модель персонального кабінету з Firebase Authentication, Cloud Firestore, міграцією локальних даних і вимогами до безпеки описано у [ROADMAP.md](ROADMAP.md). Спільні кабінети закладу та ролі користувачів до першого етапу не входять.

## Розробка

Вихідний код залишається модульним у `js/*.js`. Після змін виконайте:

```bash
npm test
```

Команда перебудовує browser bundles і запускає Node-тести.
