# QA report — MVP 1.3

Дата збірки: 2026-08-10.

## Автоматичні перевірки

`npm test` проходить успішно.

Перевіряється:

- валідність схем усіх 26 шаблонів;
- дублікати `id` у вкладених `repeatable`;
- коректність місячних metadata;
- XML escaping, включно з U+FFFE/U+FFFF;
- небезпечні XML/HTML-рядки;
- CRC32 та ZIP/OOXML структура DOCX;
- стандартний, паперовий і графічний режими бланка;
- генерація DOCX для кожного шаблону на тестових даних;
- production `index.html` використовує classic `app.bundle.js`, тому підтримує пряме відкриття через `file://`;
- наявність UI для збережених наказів, універсальних шаблонів і JSON-перенесення профілю;
- санітизація запису збереженого наказу, включно з видаленням control chars та ключів `__proto__`.

## Статичний smoke-check

Окремо перевірено, що всі `el("...")` посилання в `app.js` мають відповідні унікальні `id` в `index.html`, а production bundle проходить `node --check`.

## UX regression checklist

- місяці та категорія стоять в одному рядку на широкому екрані;
- картки каталогу починаються одразу після компактної панелі фільтрів;
- універсальні шаблони показуються окремо внизу;
- A4 preview відкривається тільки у modal;
- є окремий розділ `Збережені`;
- збережений наказ можна редагувати, копіювати та видаляти;
- копія не успадковує номер наказу;
- накази не автозберігаються;
- профіль можна перенести JSON-файлом;
- saved-orders backup винесено окремо і супроводжено попередженням про персональні дані.

## Відома межа середовища тестування

Headless Chromium у поточному контейнері зависає навіть на локальному `file://` smoke-run, тому я не позначаю повний GUI E2E як пройдений. Функціональна логіка, bundle, schema, DOCX та статична цілісність перевірені автоматично; перед масовим розгортанням потрібен короткий ручний smoke-test у Windows-браузері.
